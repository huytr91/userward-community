# Introducing Userward

## AI that answers to you

Userward is an AI manager designed to work for the user—not for a model provider.

Most AI products ask people to choose a model, engineer prompts, manage context, estimate cost, understand tool limitations, and notice when an answer was never actually executed. Userward reverses that relationship. The user describes the outcome they want; the product determines what must be clarified, what information is necessary, what tool or model is appropriate, what it should cost, and what cannot happen without approval.

## Why the name Userward?

The suffix “-ward” means “in the direction of,” as in *forward* or *homeward*. **Userward** means that every routing, privacy, budget, memory, and execution decision moves toward the user’s interests.

The previous name, Minimum, remains in the product as the **Minimum Context Engine**: the technology responsible for selecting the smallest sufficient context for a task. Userward is the product and its duty; Minimum is one of the methods it uses.

## The user-interest promise

Userward is built around four duties:

1. **Loyalty** — Never prefer a provider because it benefits the platform. Choose the least expensive qualified route and disclose commercial influence.
2. **Care** — Clarify material ambiguity, select deterministic tools before probabilistic models when appropriate, verify risky outputs, and never claim execution without evidence.
3. **Disclosure** — Show what data will be sent, what model or tool will be used, what the task may cost, and what actually happened.
4. **Obedience** — Stay within the confirmed goal, budget, data policy, and permissions. Never create an external side effect without approval.

## How Userward works

```text
User goal
  → Plain-language clarification
  → Confirmed goal contract
  → Capability and privacy assessment
  → Tool-first, model-second routing
  → Minimum sufficient context
  → Budget-aware execution plan
  → User approval where required
  → Verified execution
  → Receipt with evidence, data use, and real cost
```

## What makes it different

Userward is not another multi-model chat interface. Multi-model access, RAG, project memory, cost dashboards, and tool calling already exist in many products. Userward’s differentiation is the unified management layer that represents the user across all of them.

The product should be able to answer, before spending tokens:

- Is AI needed at all?
- Which information is materially necessary?
- Should a deterministic tool be used first?
- Which qualified model is the least expensive?
- What data will leave the device?
- What level of verification does the task require?
- Which actions need explicit approval?

After the task, it should provide evidence:

- models and tools actually used;
- files and data actually accessed;
- changes actually performed;
- checks actually completed;
- input/output tokens and provider cost;
- fallbacks, retries, limitations, and failures;
- context avoided without reducing the required quality.

## Product architecture

Userward is intended to evolve around these independent engines:

- Goal Contract
- Clarification Engine
- Capability Registry
- Routing Engine
- Minimum Context Engine
- Budget Manager
- Privacy Broker
- Safety Engine
- Execution Planner
- Memory with provenance
- Execution Receipt

## Editions

**Userward Community** contains chat, supported file analysis, project history, folder-scoped coding, patch approval, measured usage, and the public policy framework.

**Userward Personal** may include private local connectors, media tools, documents, email/calendar actions, deployment, RPA, and desktop integrations. Every adapter must return execution evidence and respect the same approval policy.

## Success is not engagement

Userward should not optimize for message count or token consumption. Its north-star metric is:

> The percentage of user goals completed within the confirmed quality, cost, privacy, and permission boundaries.

Supporting measures include first-pass success, cost per completed outcome, unnecessary context avoided, routing regret, memory citation accuracy, safety false positives, and unapproved external side effects—the last of which must remain zero.

## Positioning

> **Userward is the AI manager that works for you—not for a model provider. It decides what information is needed, what tools should be used, what you should pay, and what must never happen without your approval.**
